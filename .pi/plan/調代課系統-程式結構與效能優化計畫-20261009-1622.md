# 調代課系統：程式結構與效能優化計畫

## 一、現況體檢（實測數據）

以下皆為本次實際執行量測所得，非估計值。

### 1. 前端載入體積

| 產出物 | 原始 | gzip | 狀態 |
|---|---|---|---|
| `assets/index-*.js`（主包） | 1,172 kB | 358.6 kB | 超出 Vite 600 kB 警告閾值近一倍 |
| `assets/exceljs.min-*.js` | 938 kB | 270.9 kB | 已成功懶載 |
| `assets/jszip.min-*.js` | 97 kB | 30.2 kB | 已成功懶載 |
| `assets/vendor-*.js` | 74 kB | 29.3 kB | vue＋pinia |
| `style.css`＋`mobile.css`＋`onboarding-tour.css` | 178 kB | 未壓縮 | **render-blocking** |

匯出模組（accounting／invigilation／activity-cover／period8／school-timetable）已正確分包，這部分做得好。

### 2. 首屏阻塞的三個確切原因

1. **CSS 內嵌 `@import` 串行請求**：`public/style.css` 第 5 行為 `@import url('https://fonts.googleapis.com/css2?family=Outfit...&family=Noto+Sans+TC...')`。瀏覽器必須先下載並解析 152 kB 的 CSS，才會發現字型 URL，再發第二次請求。這是 CSS 性能最經典的反模式，且違反 README 所述「無 CDN、離線自包含」的架構約定。
2. **CSS 未壓縮、未 hash、無快取標頭**：`style.css` 為 6,638 行原始碼（平均行長 22.9），且放在 `public/` 直出。`vercel.json` 只對 `/assets/(.*)` 給了 `Cache-Control: public, max-age=31536000, immutable`，而 `style.css`、`mobile.css`、`onboarding-tour.css`、`/templates/*.xlsx` **完全沒有 Cache-Control**，檔名又無 hash。結果是要嘛每次重抓 178 kB，要嘛吃到舊版 CSS 造成樣式錯亂。
3. **主包過大**：`App.vue` 靜態載入全部 28 個 modal（含 `MatchDrawerModal` 51 kB、`CompareModal` 46 kB），且管理員專用的 `ui-admin.js`（2,731 行）、`ui-backoffice.js`、`domain-billing.js`（2,363 行）、`print-helper.js`（1,603 行）全部進首屏。多數使用者是教師，卻要下載整套後台邏輯。

另有一條建置警告：`export-lazy.js` 被 `stores/data.js` 動態 import，卻又被 `ui-export.js`、`ui-report.js` **靜態 import**，破壞了分包語意（目前匯出 chunk 僥倖仍切得出來，但機制不正確）。

### 3. 程式結構

| 位置 | 規模 | 問題 |
|---|---|---|
| `src/App.vue` | 2,870 行（模板 2,717 行） | 單一殼層過大；222 個 `v-if`、0 個 `v-show` |
| `src/modules/ui-timetable.js` | 3,178 行 | 單檔超過可維護閾值 |
| `src/modules/ui-admin.js` | 2,731 行 | 同上 |
| `src/modules/ui-activity.js` | 2,183 行 | 同上 |
| `src/domain/domain-billing.js` | 2,363 行 | 純領域邏輯，分層正確但過大 |
| `src/stores/` 15 個 store | 共 630 個 `(...args)` 轉發函數 | 純樣板層。timetable.js 102 個、output.js 98 個、data.js 68 個、session.js 58 個 |
| `code.gs` | 9,999 行 | `doPost` **單一函數 2,045 行**、`handleReadAction_` 505 行、`buildMatchCandidates_` 394 行 |

store 之間互相 import（`data.js` 引 13 個 store、`timetable.js` 引 12 個），形成網狀耦合，是轉發層氾濫的根因。

**做得對的地方**：`domain/` 純邏輯分層良好可單測、GAS 快取已有 TTL 分級與 chunked cache＋generation bust、鎖等待已分級（20s／10s／5s）、匯出懶載已落地。

### 4. 開發體驗

- **`npm test` 跑 466 秒**（7.8 分鐘）。其中 `collect` 606 秒、`environment` 212 秒；`module-deps-tests.test.js` 單檔就吃掉 **146 秒**。
- **`npm run lint` 現在跑不起來**：`node_modules/eslint` 存在，但 `node_modules/.bin/eslint.cmd` 不存在，bin 連結遺失。

## 二、優化計畫

### Phase 1：載入效能（本輪實作，風險低、效益最大）

**1.1 解除字型串行請求**
- 檔案：`public/style.css`、`index.html`
- 移除 `style.css` 開頭的 `@import url(googleapis...)`，改在 `index.html` `<head>` 以 `<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>` 加 `<link rel="stylesheet" href="https://fonts.googleapis.com/...">` 放在 CSS 之前，讓字型與 CSS 並行下載。
- 若要徹底符合「離線自包含」架構約定，改為自託管 Noto Sans TC 子集（僅常用字）＋系統字型 fallback。此為可選加碼，預設先做並行化。

**1.2 CSS 交給 Vite 處理**
- 檔案：`public/style.css`、`public/mobile.css`、`public/onboarding-tour.css`、`src/main.js`、`index.html`
- 把三個 CSS 移入 `src/styles/`，由 `main.js` 以 `import './styles/style.css'` 載入。Vite 會自動壓縮、加上 content hash、輸出到 `dist/assets/`，因而吃到 `vercel.json` 既有的 immutable 一年快取。
- 預期：178 kB 未壓縮 → 約 85～95 kB 壓縮，且二次造訪零下載。
- 風險控管：純檔案搬移，class 名稱與選擇器完全不動。搬移前先確認無 JS 動態插入 `<link>` 或依賴固定路徑的程式碼。

**1.3 補齊快取標頭**
- 檔案：`vercel.json`
- 為 `/templates/(.*)` 新增 `Cache-Control: public, max-age=31536000, immutable`（範本 xlsx 已隨 build 產出於 `dist/templates/`）。若 1.2 採保留原路徑方案，則一併為三個 CSS 補標頭。

**1.4 Modal 非同步化**
- 檔案：`src/App.vue`
- 28 個 modal 中，僅保留首屏必要者同步載入（`LoadingOverlay`、`LoginCard`、`ClassPanel`、`TeachersTable`），其餘 24 個改 `defineAsyncComponent(() => import('./components/XxxModal.vue'))`。
- 預期主包減少約 150～200 kB。

**1.5 修正 `export-lazy` 分包破口**
- 檔案：`src/modules/ui-export.js`、`src/modules/ui-report.js`、`src/modules/export-lazy.js`
- 將 `ensure*Ready` 閘門抽出為獨立的 `src/modules/export-gates.js`，讓 `ui-export`／`ui-report` 只靜態引用閘門、不靜態引用 `export-lazy.js` 本體。建置後警告應消失。

**1.6 依角色切分後台模組**
- 檔案：`src/App.vue`、`src/stores/admin.js`、`src/stores/backoffice.js`
- `ui-admin.js`（2,731 行）與 `ui-backoffice.js` 僅被各自的 store 引用，是理想的分包邊界。改為進入管理員頁籤時才動態載入對應 store。
- 這是 Phase 1 中風險最高的一項，會排在最後做；若牽動過廣則獨立成 Phase 1.5 單獨交付。

**Phase 1 驗收標準**
- `npm run build` 主包 < 700 kB（gzip < 220 kB），且不再出現 chunk > 600 kB 警告與 `export-lazy` 分包警告。
- `npm run e2e:boot` 通過（開機自檢）。
- `npm test` 全數通過（60 檔／105 測），無回歸。
- DevTools Network 確認：CSS 與字型為並行請求、二次造訪 CSS 快取命中（memory disk cache）。

---

### Phase 2：前端結構重整

**2.1 App.vue 降維**
- 把 2,717 行模板依頁籤切成 `src/features/` 子元件（timetable／requests／admin／output／history…），App.vue 只留導覽與 modal 掛載。
- 納入既有 `tests/composition.test.js` 聚合檢查，避免模板綁定斷裂。

**2.2 移除轉發樣板層**
- 目標：630 個 `(...args)` 轉發函數歸零。
- 做法：讓 store 直接 `return { ...UiTimetable(deps) }` 或明確命名委派，消除 `const xxx = (...args) => yyy(...args)` 這種無資訊中介層。
- 每移除一批就跑 `tests/__appmap.json` 與 `tests/__storeReturns.json` 契約測試，確保公開 API 不變。

**2.3 超大模組拆檔**
- `ui-timetable.js` 3,177 行、`ui-admin.js` 2,731 行、`ui-activity.js` 2,183 行、`domain-billing.js` 2,363 行，各按職責切成 3～5 個子模組。

**驗收**：`npm run lint` 零錯誤、`npm test` 全過、公開 store API 由契約測試鎖定不變。

---

### Phase 3：GAS 後端重整（`code.gs` 9,999 行）

**3.1 拆解 `doPost`（2,045 行）**
- 改為 action 路由表：`{ action: handlerFn }`，依業務域切成 request／approval／quota／triangle／schedule-import／school-swap／homeroom 等處理器群組。
- GAS 支援多個 `.gs` 檔同專案，可拆成 `code-gs/` 下多檔再合併，或維持單檔但函數分組。

**3.2 拆解 `handleReadAction_`（505 行）** 同上，改為讀取端路由表。

**3.3 讀取路徑檢視**
- 目前 `sheet.getDataRange().getValues()` 全表掃描 4 處、`getRange` 18 處。逐一檢視是否可收斂為單次批次讀取，降低 GAS 執行時間配額消耗。

**驗收**：`npm run lint:sync-gas` 後 `tests/gas.test.js`、`tests/code-gs-contract-tests.test.js` 全過；GAS 行為契約不變。

---

### Phase 4：開發體驗

**4.1 修復 ESLint**：`node_modules/.bin/eslint.cmd` 連結遺失，重新建立或重裝 devDependencies，`npm run lint` 需可執行。

**4.2 加速測試**：`module-deps-tests.test.js` 單檔 146 秒，改為以檔案 mtime／hash 快取掃描結果，僅在來源變動時重掃。目標整體測試時間 < 120 秒。

**4.3 補齊效能基線**：`docs/perf-baseline.md` 目前基線表全是 `___ ms` 未填。Phase 1 完成後依表內六個場景實測填入，作為日後回歸門檻。

## 四、本輪建議實作範圍

**Phase 1 的 1.1～1.5**（字型、CSS、快取標頭、Modal 非同步化、export-lazy 分包修正）加 **Phase 4.1（修 ESLint）**。這批改動互相獨立、風險低、可一次驗收，且直接改善首次載入與二次載入體驗。1.6 與 Phase 2～4 建議另開輪次，各自有獨立驗收標準。
