# RDQ 需求規格：代課費專案款項分表

## 一句話任務
部分代課費改由專案款項支應，這些節數從「公付代課」表移到各自的專案工作表，超鐘點沖減規則完全不動。

## ✅ 已確認
- **代課費來源由申請單決定**：新增「代課費來源」欄，教學組逐筆指定專案；空白＝維持公付。（Ⅲ）
- 專案節數**從公付代課表移除**，只留在專案表；兩表相加才等於原本的公付總額。（Ⅲ）
- **超鐘點照原本扣**：請假原堂為超鐘點時仍沖原教師超鐘點，專案只影響代課費由誰付。（Ⅲ）
- 表長相：**每個專案各一張工作表**，如「公付代課-〈專案名〉」，沿用公付代課版型。（Ⅲ）
- 專案名稱**集中維護成下拉清單**，避免手打不一致把同一專案拆成多張表。（Ⅳ）

## ❓ 假設
- 只有「公付性質」的代課吃這個欄位；自付代課與代導鐘點不受影響（本來就是教師自付／另表）。
- 舊資料無此欄＝空白＝公付，結算結果與改版前完全相同。
- 「公付代課-身心調適假」比照同一規則分表。
- 小鐘點（課表代課）已走自己的計畫分表，本次不動。
- 專案表動態複製公付代課版型產生，**不新增範本工作表**；範本仍只有五張固定表。
- 紀錄保存的是專案**名稱字串**（與既有 `subFee` 一致），清單改名不回溯既有紀錄。
- 匯出前摘要列出「固定表＋各專案表」的筆數與金額。

## ➕ 已採納（象限Ⅳ）
- 專案名稱集中維護成下拉清單：後台單一專案清單（新增／改名／停用），申請單改為選單取值。

## ❌ 排除項
- 不做專案核定文號、經費上限與超支檢核。
- 不做專案歸屬改錯的調整單流程。
- 不做專案與公付的交叉核對表。
- 不做「來源空白或專案未核定」的匯出前待補清單。
- 不重算或覆蓋既有月份歷史報表。
- 不改動自付代課、代導鐘點、小鐘點與超鐘點的沖減邏輯。

## 📋 一段式需求規格
請在專案 **school-substitution-sys** 中，讓代課費可以指定專案款項支應。在調代課申請單新增「代課費來源」欄，值由後台集中維護的專案清單下拉選出（可新增、改名、停用；紀錄保存名稱字串，改名不回溯），空白一律視為公付。月報與會計匯出時，已指定專案的代課節數從「公付代課」工作表移除，改列入「公付代課-〈專案名〉」工作表，每個專案一張，動態複製公付代課版型與簽核區產生，不新增範本工作表；「公付代課-身心調適假」比照處理。既有超鐘點沖減規則完全不變：請假原堂為超鐘點者仍沖原教師超鐘點，專案只改變代課費由誰支付。自付代課、代導鐘點與小鐘點維持現狀。舊資料無此欄位時結果必須與改版前逐筆相同，且不重算既有月份歷史報表。匯出前摘要需列出固定五表與各專案表的筆數與金額。

## ✔ 驗收條件
- [ ] 申請單填「代課費來源＝某專案」後，該節不出現在公付代課表，改出現在「公付代課-某專案」表。
- [ ] 未填的紀錄，公付代課表節數、金額與改版前逐筆相同。
- [ ] 同月兩個專案產生兩張專案表，合計與各自筆數正確。
- [ ] 超鐘點表節數與金額在專案情境下與改版前完全相同。
- [ ] 單次下載的 Excel 含五張固定表＋N 張專案表，版面與簽核區可直接送會計。
- [ ] 專案清單改名或停用後，既有紀錄仍列在原專案名稱表，不跳表。
- [ ] 既有測試全綠，並補專案分表、舊資料相容、超鐘點不受影響三類回歸測試。
